\sub{Scalars}
\code{order_number} and \code{supplier} each hold one value.
\sub{List}
\code{items} holds two records. Each record has its own description, quantity and unit price.
\sub{If the scalars + lists plan runs}
Read the scalar fields separately; read item rows in page chunks; combine them into the one candidate shown above. Checks happen afterward.
\end{minipage}

\textbf{Schema versus answer:} \code{properties} names the requested fields; \code{type} sets their data types; \code{items} defines the structure of each array entry; \code{required} lists keys that must be present. The answer contains values, not these schema declarations.

This small source may fit the whole-document plan. The example demonstrates the scalar/list split, not a measured execution of the fallback plan.
